## 联调中发现并修复的问题

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 电脑新建对话跑完一轮后，手机一直显示「正在进行」、看不到回复；本机 link 被冻结为 `REMOTE_EPOCH_STALE` | P1 在同一 `metadataVersion` 下把 `updatedAt` 变化判为 `REMOTE_SYNC_CONFLICT`；而消息与运行活动按契约本来就不增加元数据版本。P2 又把连接中收到的 `worker.hello_rejected(REMOTE_SYNC_CONFLICT)` 误报成 `REMOTE_EPOCH_STALE` | 联调修复 1（`R15-joint-fix-1.md`）：服务端只比较真实元数据字段，活动时间单调更新；Worker 保留服务端的真实错误码；`busyFresh=false` 时视图输出 `busy=false`，断线或冻结时发失效事件 |
| 断线或 Hub 重启后，未获许可的预留让对话长期显示忙碌 | 预留过期只在连接存活时检查 | P2 返修 1：只读路径排除过期预留；独立的 1 秒清理任务；启动时先释放遗留预留 |

## 待决与后续

1. **产品待决：取消后「继续」失败。** 取消一轮后，对话再用 continue 模式发送，会返回结构化的 `SESSION_NOT_RESUMABLE`（「上一轮会话已关闭，不能原生续接」）。这是 R1.5 之前电脑端就有的 Session 规则，不是 R1.5 引入的回归；但手机默认用 continue，用户取消后需要手动选「新一轮」。是否改成自动回退到最近一个可续接的会话，需要产品决定。
2. P2 清理任务偶发的重试日志只输出固定文案，没有异常类型，原因未归因。后续让它记录异常类型（不含正文）。
3. 同步进度状态（补传中 / 已同步 / 异常）不在 0.7.0 协议里，属于协议后续项。
4. 单个对话删除的本机入口未冻结，属于后续项。
5. 手机界面的真机验收（扫码、分组、忙碌置灰、离线提示）放在阿里云部署后进行。
