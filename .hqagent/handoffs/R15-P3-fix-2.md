# R1.5-P3 返修 2：手机端真机体验问题

用户用真机试用后提出三处问题，产品决定已经确认。只改 `apps/desktop/**` 和 `.hqagent/handoffs/**`，不改协议和后端。类型一律从 `@hqagent/protocol` 导入，不要自造字段。

## A. 已撤销的设备默认隐藏（`RemoteDevicesPage.vue`、`remote-chat.store.ts`）

现状：服务端没有删除设备的接口（0.7.0 也没有），`status=revoked` 的设备一直留在「我的电脑」列表里。

要求：
- 列表默认只显示未撤销的设备；已撤销的收进列表底部一个可折叠的「已撤销（N）」分组，默认折叠，只能看、不能进入。N 为 0 时不显示该分组。
- 当前选中的电脑被撤销后，回到设备列表并提示「该电脑已撤销」。
- 撤销确认弹窗补充两句说明，保留原有的安全提示：
  - 「撤销后这台电脑需要在电脑端重新生成二维码配对，重新配对会作为新设备出现。」
  - 「只是暂时不用的话不必撤销，关闭电脑上的 Hub 即可，下次打开会自动重连。」

## B. 手机端「新建任务」（`RemoteChatPage.vue`、`remote-chat.store.ts`）

现状问题：
- 不能选项目：`RemoteChatPage.vue:244` 固定用 `catalog.workspaces[0]`，目录没加载时填假值 `workspace_demo`，创建必然失败；
- 场景写死三个选项，`sceneVersion` 固定为 1；
- 名称叫「新建远程对话」，和电脑端的「新建任务」不一致。

要求（用户选定：**先建任务，建好后再在输入框发第一条消息**，和电脑端一致）：

1. 名称统一为「新建任务」。入口两处：
   - 对话列表顶部的按钮；
   - 每个项目分组标题旁的「+」，从这里进入时，项目默认选中该分组。
2. 弹窗字段：
   - **项目**：下拉，选项来自当前选中电脑的 `RemoteCatalogView.workspaces`（显示名称）；
   - **场景**：下拉，选项来自 `RemoteCatalogView.scenes`，显示场景名，提交时使用该场景的真实 `sceneId` 和 `version`；
   - **标题**：选填。为空时用「新任务 MM-DD HH:mm」，因为协议要求 `title` 必填。
3. 目录未加载或加载失败时，项目和场景下拉显示「正在读取电脑的项目列表…」或错误提示，创建按钮不可点，并提供重试。打开弹窗时如果还没有目录，主动拉取一次（`GET /devices/{workerId}/catalog`）。
4. 电脑离线时点创建，立即提示「设备离线，发送失败」，不发请求（沿用现有逻辑）。
5. 创建后沿用返修 1 的占位流程：显示「正在电脑上创建…」，真实对话同步回来后自动选中并打开，**光标聚焦到输入框**。
6. 清理 R1 离线排队的遗留 UI，例如「撤回排队指令」弹窗和 `queued_offline` 相关文案：
   - 先核对契约 `packages/protocol/remote/R1.5-contract.md`：修订 2 下，撤回在 30 秒送达窗口内是否仍有可达的状态；
   - 不可达就删除；仍可达就保留，但文案改成与 R1.5 一致；
   - 在回执里写明判断依据。

## C. 顶部状态卡片默认收起（`RemoteChatPage.vue`）

现状：对话顶部常驻「1. 传输状态 / 2. 控制结果 / 3. 执行状态」三栏卡片。R1.5 取消离线排队以后，前两项几乎不会变化，对普通使用没有意义。

要求：
- **默认收起。** 标题栏只显示一个小状态标记，按当前 run 状态显示：运行中 / 等待审批 / 已完成 / 已失败 / 已取消；没有 run 时不显示。
- 点击状态标记展开详细的三项，再点收起。展开状态只在当前页面内记住，不写入持久化存储。
- 出现以下需要注意的情况时**自动展开**，并在标记上显示提醒色：
  - 控制结果为 unconfirmed；
  - 送达失败或过期（`REMOTE_DELIVERY_EXPIRED` 等）；
  - run 失败。
- 移动端（375 宽）不能再挤占消息区域。
