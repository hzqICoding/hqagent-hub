本文是二期设计输入，不是已实现功能清单或冻结后的接口规范。本次仅归档讨论，不启动手机端开发。具体传输、部署和接口字段需在二期开工前确定。

## 1. 已确认的产品方向

- 核心能力由统一协议、后端接口和 Worker 承载，桌面、浏览器、手机复用同一套任务编排。
- 手机和电脑操作同一份任务对话，不分别维护两套互不关联的聊天历史。
- 手机可选取目标电脑上的项目目录；用户已认可由电脑服务提供目录列表、手机逐层浏览并选择的方式。
- 项目下可创建多个任务对话。侧边栏组织为“项目 → 任务对话”，不同任务分别保存消息和 Agent 会话关联。
- 模型品牌与角色解耦；后续允许扩展场景、角色和 Agent Adapter。

## 2. 概念及会话规则

```text
目标电脑（Worker）
  └─ 项目／Workspace：绑定该电脑上的目录
       └─ 任务对话／Conversation
            └─ 多轮执行／Run
                 └─ 角色执行节点 → 对应 Agent 的原生 session/thread
```

“任务对话”是面向用户的长期聊天容器，不等同于现有内部 Task。当前 Run 会关联实际执行 Task；后续协议映射须保留这些区别，不仅凭界面称呼重命名数据结构。

建议交互：新建任务首次执行创建新 Agent 会话；已有任务默认继续对应角色会话；“重置 Agent 上下文”移入更多菜单。重置是否携带历史摘要需显式说明。恢复失败须提示，不能静默新建并假装保留上下文。

当前产品仍使用 New／Continue 显式选择，上述默认行为和侧边栏调整尚未落地。页面历史保留不代表模型自动读过全部历史。手机、电脑切换查看不应触发新 session；同一项目不同任务不默认共享 session。

## 3. 手机操作流程

1. 绑定并选择目标电脑，查看在线状态。
2. 选择已有项目，或浏览该电脑允许访问的目录并登记项目。
3. 打开已有任务继续对话，或在项目下新建任务。
4. 发送文字、截图、附件；消息持久化后取得接收回执。
5. Worker 按场景配置调用模型，在授权目录或隔离 worktree 执行。
6. 两端同步展示消息、进度、审批、取消状态和最终结果。
7. 如后续授权打包或上传，展示真实产物及下载入口；没有相关能力时明确报告缺口。

电脑端应同时看到手机发来的消息和新建任务；手机也应看到电脑端的操作。关闭界面不等于停止 Worker。电脑关机、休眠或服务离线时必须显示离线，不能声称正在执行；是否支持离线排队另行确定。

## 4. 手机如何选目录

| 入口 | 操作 | Worker 职责 |
| --- | --- | --- |
| 已登记项目 | 选择名称，如“Q20 地面站” | 解析 workspaceId 与所属电脑上的目录映射 |
| 浏览目录 | 根目录 → 子目录 → 选择此目录 | 返回允许浏览的根与子目录，校验最终路径后登记项目 |
| 手动输入 | 输入电脑绝对路径 | 校验存在性、目录类型和访问范围 |
| 新建项目（扩展） | 选择父目录并输入名称 | 校验后创建目录、登记项目；初始化代码是后续执行步骤 |

手机不使用自身文件选择器来选择电脑目录，也不能复用只会在电脑弹窗的原生目录选择接口。电脑可使用原生选择器，手机使用远程目录列表，两者最终复用项目登记能力。

接口应覆盖：目标设备、允许浏览根、子目录分页或数量限制、选定目录校验、项目登记、目录创建及失败原因。路径语法和真实路径解析由目标 Worker 负责；不得假定所有设备都有 Windows 盘符。符号链接或 junction 不得绕过允许访问范围。浏览目录本身无需模型。

自然语言“切到 Android 项目”优先匹配已登记名称或别名；歧义时选择，未找到时进入目录选择。不要让模型猜测路径直接执行。

## 5. 模型调用与交接边界

```text
用户消息 → Worker → 规划 Agent
                 ← 规划结果
          Worker → 实施 Agent
                 ← 改动、测试、产物
          Worker → 验收 Agent
                 ← 验收结论 → 两端同步
```

- Worker 调度 Agent；当前不是 Claude 自己启动 Codex，也不是模型直接共享完整上下文。
- 每轮冻结场景配置；同一对话消息按轮次排队。并行写任务继续采用隔离 worktree。
- 每个角色独立配置运行时、模型、推理等级和职责；后端执行目录范围、权限和审批规则。
- 普通阶段当前主要交接上游结果摘要与实际改动路径，尚非完整结构化任务拆分协议。
- 原规划会话验收已经实现：恢复该轮原 planner session，通过固定证据包核对实施交付。
- 后续应标准化交接：目标、约束、验收条件、完成状态、改动、可核验测试记录、产物引用、阻塞和待确认事项。区分模型自述与 Worker 观测证据。
- 轻量模型意图识别属于未来可选入口：提出场景和参数建议，Worker 校验后执行；尚未实现通用动态路由、任意并行拆分或自动返工闭环。

## 6. 场景、角色与插件扩展

| 对象 | 职责 |
| --- | --- |
| 角色模板 | 职责、输入输出约定、权限、所需能力 |
| 场景模板 | 步骤、依赖、角色引用、交接与验收规则 |
| Agent 绑定 | 各步骤使用的运行时、模型及推理等级 |
| 能力插件／Adapter | 在声明能力和权限范围内接入模型、工具或外部服务 |

当前 LocalSceneId 固定为 analyze／plan／develop，场景角色集合在后端受限；可以编辑已有角色配置，不能通过前端加按钮就获得任意角色创建能力。公共 RoleId 已预留开放扩展，但角色定义、权限注册、存储、接口及工作流校验仍需补齐。

后续自由创建与配置应建立在版本化协议上；插件声明能力不等于获得执行授权。MCP／skills 可提供工具和操作指导，但不能替代 Worker 的状态、审批及交付校验。

## 7. 跨端同步及接入契约要求

- 明确权威记录归属：执行状态由目标 Worker 确认，接入服务回执仅表示收到或转交，不能冒充执行成功。
- 设备绑定、身份认证、访问授权及撤销能力独立设计；不得将本机 Hub Token 发给手机或直接暴露现有本机接口。
- 消息和控制命令包含唯一标识，重复提交幂等；两端同时操作同一审批或任务时需冲突处理。
- 事件具备顺序与游标，支持断线补发、去重和快照恢复；桌面与手机显示同一任务状态。
- 审批、拒绝、取消从任一端操作后同步到另一端。任务终止应使未决审批失效，不能留下仍可操作的旧申请。
- 截图和附件关联消息／任务，由 Worker 取用；存储位置、大小限制、模型视觉支持和保留时间待设计。
- 下载链接须指向实际产物，访问权限和有效期另行制定。
- WebSocket／MQTT、云端中转或其他部署拓扑尚未选定；领域接口与传输方式解耦。

## 8. 二期前置缺口与可复现验收

当前可复用：项目登记、对话／Run、场景配置、原生会话恢复、事件、审批和原规划会话验收。待建设：远程设备接入、目录浏览、附件传输、跨端同步整合、产物访问以及自定义场景／角色管理。

本地测试还发现：任务取消后旧审批仍可记录为 approved；该轮没有实际写入，但审批与终态联动需要修复。运行中命令真正停止的验收尚未完成，不能把“等待审批时取消”当作已通过。详见 `../reviews/N0-cancel-running-task.md`。

二期验收场景：

1. 手机选设备与目录、新建任务，电脑出现同一项目和对话。
2. 两端交替发消息，消息去重，继续的是同一任务各角色的正确 session。
3. 手机离线期间电脑执行，重连后补齐消息及事件，不重复启动任务。
4. 两端重复批准或取消，只发生一次有效操作；终止后的旧审批不可再放行。
5. 心跳命令实际启动后取消，核对进程退出、文件停止更新及最终状态同步。
6. 目录不存在、无权限、越界路径、链接越界及设备离线均显示明确原因。
7. 手机发送截图，Worker 与选定模型确实可读取；不支持时明确报告能力缺口。
8. 对授权打包上传任务，手机可取得真实产物并下载安装验证；失败不生成虚假成功链接。

## 9. 下一步设计顺序

先核对现有领域契约及取消／审批缺口，再定义远程设备与目录接口、同步和附件契约，最后建设接入服务与手机界面。二期开工时确定身份与设备绑定、离线消息策略、传输协议、部署方式、附件存储及产物访问策略。此次共识不授权部署公网服务或执行新的业务项目任务。
