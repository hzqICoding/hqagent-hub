# R1.5-P3 前端任务：多电脑列表、两端对话互通、忙碌锁、可见性

设计基线：`docs/vnext/手机远程接入方案.md` §11（v0.4）。开工前请完整阅读 §11，重点是 11.3–11.8。

## 开工前提（按顺序）

1. **先完成并提交手上的 P3-B 返修 2**（B4–B7，含扫码配对）。主代理审核通过后，会把它合入 `integration/phase1`。
2. **协议 0.7.0 冻结后，主代理会通知你**，同时给出新的 worktree 和一份「接口对照」（新增字段名、路由、错误码）。本文中凡写「以 0.7.0 schema 为准」的地方，都以那份对照和 `@hqagent/protocol` 的生成类型为准，**不要自造类型**。
3. 收到通知前可以先读 §11、熟悉现有页面、规划组件，但不要提交依赖新类型的代码。

## 产品规则（与 R1 不同的地方，务必记牢）

- **电脑是唯一写入方**，服务器保存完整副本。两端都能直接继续任意对话。
- R1 的**「远程对话在电脑上只读」规则取消**（P3-C 做的只读限制要撤掉）。
- R1 的**离线排队取消**：电脑离线时，手机上发消息、控制、审批、改对话都**立即失败**，提示「设备离线，发送失败」，已输入的文字保留。不再出现「电脑离线，指令已排队」。
- **不能同时进行**：对话中有一轮处于排队、运行、待审批时，另一端的发送按钮置灰。**「取消」永远可用。**
- 可见性三档：两端可见（默认）、仅电脑、仅手机。**只是显示区分，不是保密**，内容照样存在服务器上。

## 手机端（远程 H5，`pages/remote/**`、`stores/remote-*.ts`、`shared/api/remote-*`）

1. **「我的电脑」列表**：登录后的第一页。列出已配对的电脑及在线状态，每 15 秒刷新，页面不可见时暂停。选中一台后进入它的工作区；顶部显示当前电脑并可切换，切换后清空当前数据、重新加载。当前选中的电脑可以放在路由参数里，**不要**写入 localStorage 等存储。
2. **按项目分组的对话列表**：展示所选电脑的对话，按项目（workspace）分组，与电脑工作台一致。显示最近活动时间、忙碌标记、可见性标记。列表分页加载。
3. **两端对话都可以继续**：包括电脑上创建的对话。新建对话时选择项目和场景（沿用 catalog）。
4. **忙碌锁**：
   - 对话忙碌时发送按钮置灰，提示「电脑上正在进行，结束后再继续」。
   - 服务端返回忙碌错误码时，给出同样的提示，并保留输入。
   - 取消按钮不受限制。
5. **离线直接失败**：
   - 设备离线时，发送、控制、审批、改标题、改可见性都立即提示「设备离线，发送失败」，输入保留；
   - 去掉所有「已排队」的展示和「撤回排队指令」的入口；
   - 三层状态面板里的「传输状态」只保留在线/离线和已投递。
6. **消息按需加载**：
   - 打开对话先加载最近一页；向上滑到顶部时加载更早的一页，并保持当前阅读位置不跳动。
   - 新消息通过增量事件追加到底部。
   - 分页与增量事件的合并按 messageId 去重。
7. **对话设置**：改标题、归档，以及可见性（两端 / 仅电脑 / 仅手机），旁边写明「这只是显示设置，不是保密手段」。改成「仅电脑」后，这个对话会从手机上消失，要先给出确认提示。
8. 沿用 B4–B6 的修复：取最新一轮、会话模式默认值、在线状态自动刷新。

## 电脑端（本机工作台，`pages/chat/**`、`pages/remote-link/**`、`stores/chat.store.ts`、`shared/api/local-chat-*`）

1. **撤销 P3-C 的只读限制**：authority 为 remote 的对话恢复可写；保留一个小的来源标识「来自手机」即可。
2. **忙碌锁**：对话在其他端（手机）发起的一轮进行中时，发送按钮置灰，提示「手机上正在进行，结束后再继续」。取消可用。本机自己发起的一轮进行中时，行为和现有逻辑保持一致。
3. **可见性**：对话设置里加可见性选项，说明文字同上。`mobile_only` 的对话默认不出现在列表里；列表提供「显示已隐藏的对话」开关，这样才能找回它、改回可见。
4. **「连接手机」页新增同步总开关**：
   - 默认开，旁边写明「开启后对话内容会保存到你的服务器上」。
   - 关闭时二次确认：「关闭后服务器上这台电脑的对话副本将被删除，手机上将看不到任何对话」。
   - 显示同步状态：补传中 / 已同步 / 同步异常（字段以 0.7.0 schema 为准）。
