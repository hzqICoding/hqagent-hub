## 1. 你的任务

为已有 HQAgent-Hub 做可实际使用的本地聊天入口，支持“选项目 → 选场景 → 配置各角色 → 对话执行 → 查看结果 → 继续”。后端由另一个执行线实现，你只负责前端。不要从零换框架，不做手机/云端/OTA。

页面效果以清楚、紧凑、可用为主。现有 Vue 3/TypeScript/Pinia/组件/主题继续复用，不用终端样式模拟聊天，不把底层 JSON 作为用户操作表单。

## 3. 页面范围

### 3.1 本地连接页

Worker提示一次性本地连接码，用户输入后POST `/api/v2/auth/local-session`，浏览器靠HttpOnly Cookie保持会话。不要读hub.json，不把Hub Token放localStorage，不使用VITE_HUB_TOKEN。

后端未启动、连接码错误/过期、登录失效要有明确重连入口。开发时Vite代理`/api`和`/ws`到配置的Worker Base URL；只能配置地址，不能配置Token。生产Web由Worker同源提供。

### 3.2 对话工作台（主入口建议 /chat）

- 左侧：已有对话/任务列表、搜索、新建；显示项目、场景和最近时间。
- 新建时：标题、已登记项目、场景；只提交业务配置，不立即执行模型。
- 中间：消息列表、Markdown回复、输入框、发送、运行状态、错误信息。
- 右侧或抽屉：本轮场景快照、参与角色/Agent/model/effort、步骤及结果。
- 消息运行中仍可输入，下一条显示排队；重复点击不能派出多个相同请求。
- 新消息可选择“新一轮上下文”或“继续已有Agent会话”，默认首条new、后续可continue；恢复不支持时显示后端原因，不能静默伪装恢复。
- 暂停/继续/取消/重试按真实状态开放。暂停是节点间暂停，取消要等确认；不要点击后本地直接标成功。
- 各角色的过程消息与最终回复分开显示；当前角色应清楚，但不输出模型内部隐藏推理。
- 显示真实变更文件和验证结果，失败/阻塞不使用绿色完成样式。

### 3.3 场景与角色配置（建议 /scenes）

首批场景：analyze代码分析、plan需求规划、develop开发修复。

角色包括 analyst、planner、developer、可选reviewer。允许编辑Agent选择、职责提示词、modelId、reasoningEffort以及可选角色启用状态。不得在前端把只读角色改成可写或勾选伪造能力。

模型目录由后端返回；空目录且verified=false时显示未验证原因，可提供明确标注的手填输入，由后端验证。不硬编码只有某几个品牌/型号，也不把示例模型显示为已支持。

保存带expectedVersion，409时提示刷新，不能覆盖他人配置。修改配置只影响后续Run，已运行消息显示它自己的sceneSnapshot。

## 4. 唯一接口与类型

- DTO：`packages/protocol/schema/local-chat.json`，通过生成后的 `@hqagent/protocol` 导入。
- 路由：`packages/protocol/openapi/local-chat.v2.yaml`；业务行为与本文互相参照。
- 协议版本0.3.0为新增兼容字段，不修改现有v1语义。
- 响应使用既有ApiEnvelope：`{success,data,error?,requestId,protocolVersion}`。OpenAPI每个响应的x-dataSchema说明data类型。

| 操作 | 方法/路径 | data类型 |
| --- | --- | --- |
| 查询连接态 | GET /api/v2/auth/status | LocalAuthView |
| 连接本机 | POST /api/v2/auth/local-session | LocalAuthView，body LocalAuthInput |
| Agent发现/列表 | GET /api/v2/agents；POST /api/v2/agents/discover | AgentView[] / AgentDiscoveryResult |
| 模型目录 | GET /api/v2/agents/{id}/models | LocalAgentModelsView |
| 项目列表/登记 | GET /api/v2/workspaces；POST /api/v2/workspaces | WorkspaceView[] / WorkspaceView（AddWorkspaceInput） |
| 场景列表 | GET /api/v2/scenes | LocalSceneView[] |
| 保存场景 | PUT /api/v2/scenes/{id} | LocalSceneView，body SaveLocalSceneInput |
| 对话列表/新建 | GET /api/v2/conversations；POST同路径 | LocalConversationView[] / LocalConversationView |
| 读取消息 | GET /api/v2/conversations/{id}/messages?after=0&limit=200 | LocalMessageView[]，sequence升序 |
| 发送消息 | POST /api/v2/conversations/{id}/messages | HTTP202，LocalMessageReceipt，body SendLocalMessageInput |
| 对话各轮 | GET /api/v2/conversations/{id}/runs | LocalRunView[]，最新在前 |
| 某轮详情 | GET /api/v2/runs/{id} | LocalRunView，task字段包含节点/结果 |
| 控制某轮 | POST /api/v2/runs/{id}/commands | HTTP202，LocalRunView，body TaskActionInput |
| 事件补拉 | GET /api/v2/events?after=0&limit=200 | LocalEventPage，events为原HubEvent |
| 审批列表/决定 | GET /api/v2/approvals；POST /api/v2/approvals/{id}/decisions | ApprovalView[] / ApprovalView |
| 已登记会话 | GET /api/v2/sessions | SessionView[]；原生CLI全文导入不在本次 |

所有fetch设置credentials=include。写入新建对话/发送消息/控制动作/审批带Idempotency-Key；同一次操作网络重试复用key，新操作生成新key。发送消息body.clientMessageId也固定。

后端对接补充：可用 `GET /api/v2/bootstrap` 获取既有BootstrapView（Cookie认证）。旧AppLayout依赖v1/Bearer启动时，聊天入口应改用本地v2 Gateway或独立LocalLayout，不能用Mock蒙混启动。未派发Run的taskId为空字符串且task缺省；只有task存在后才能展示旧任务详情。保存scene时发送完整roles数组，包括enabled=false的可选角色。sceneSnapshot中的modelId/effort为本轮请求配置，缺省时显示“继承Runtime配置”，不要冒充已解析的实际型号。

事件初版允许使用HTTP补拉实现稳定刷新（忙时约1秒，空闲退避），后端可选提供`/ws/v2/local?after=seq`。不要依赖未经定义的新事件名；任务事件到达后重取相关Run和消息作为最终事实。游标过期按错误提示重新获取快照，不能反复重放旧消息。

未定义项目自动搜索、截图上传、APK下载、远程设备配对或插件市场入口，先不实现。目录通过现有项目登记能力选择。

## 5. 解耦开发方式

1. Gateway接口使用生成DTO，页面只依赖Gateway和store。
2. 可在src下实现MockLocalChatGateway，组合协议fixture构造场景；Mock必须显式配置，并在界面显示演示标识。
3. 真实LocalChatGateway与Mock实现同一接口，保持后端切换无需改页面逻辑。
4. 浏览器没有后端时显示连接界面，不能悄悄使用Mock并宣称执行成功。
5. 不修改既有UiGateway签名影响旧页面；新入口可使用独立LocalChatGateway。

## 6. 验收与交付

- 展示空对话、执行中、多角色交接、审批等待、失败、取消待确认、上下文恢复失败和场景保存冲突。
- 断开请求后重试使用同一幂等key，回到页面能恢复已有消息和本轮状态。
- 场景配置改变不修改过去Run的快照。
- 重复事件不重复消息；Markdown渲染不得执行用户或Agent注入的脚本。
- 主要桌面分辨率可用；窄窗口可收起侧栏，不要求本轮完成手机产品。
- 运行：`pnpm --filter @hqagent/desktop typecheck`、`pnpm --filter @hqagent/desktop test`、`pnpm --filter @hqagent/desktop build`，贴真实结果。
- 回执写入 `.hqagent/handoffs/N0-frontend.md`：提交SHA、改动目录、启动方式、测试输出、真实后端联调状态、尚未完成项。
- 未连接真实后端前只能标前端/Mock验收完成，不能宣称全产品闭环。
