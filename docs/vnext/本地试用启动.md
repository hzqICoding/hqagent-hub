`.venv`、前端依赖和`apps/desktop/dist`已在本机准备好。旧的`HQAgent-Hub-worktrees/integration`目录保留原未提交修改，不是此次新版启动目录。

## 2. 启动完整本地页面

```powershell
Set-Location 'E:\OtherPro\HQAgent-Hub-worktrees\vnext-integration\apps\hub'
../../.venv/Scripts/python.exe -m runtime.main --port 8765 --data-dir E:/tmp/hqagent-n0-trial --web-dir ../desktop/dist
```

打开`http://127.0.0.1:8765/connect`，输入控制台显示的一次性连接码。不要把Hub Token或供应商密钥填进页面。

连接码10分钟有效且只能使用一次，浏览器会话保存在HttpOnly Cookie中。Worker重启后重新连接。关闭终端会停止Worker，运行中的任务需要重新核对，首次试用先用只读场景。

## 3. 推荐检查顺序

1. 保持“真实Worker”模式，确认页面没有Mock标识；需要演示时再明确切换Mock。
2. 新建对话，展开“登记本机已有项目目录”，填写一个已有目录。
3. 选择“代码分析”，在“场景与角色”选择可用Agent及需要的模型配置。
4. 返回对话发送一个小的只读问题，核对状态、结果和错误提示；首次消息使用new。
5. 原生会话支持且上一轮成功后，用continue追问；不支持时应提示原因。
6. 验证开发场景中planner/reviewer可选、模型目录返回的effort可选择、保存只影响后续轮次。
7. 写任务只在授权的隔离工作树运行，不会自动合并回你的原分支。

本地版仍需要所选云模型的网络和额度。本轮自动化/HTTP检查通过，不代表真实模型任务已成功验收。

## 4. 重新构建或前端开发

修改前端后，在仓库根执行：

```powershell
pnpm --filter @hqagent/desktop build
```

需要Vite开发服务器时：后端增加`--environment development`；前端默认把`/api`代理到`http://127.0.0.1:8765`。改端口使用`VITE_WORKER_BASE_URL`环境变量，不能配置VITE_HUB_TOKEN。

CLI默认从Worker进程的PATH查找。只有PowerShell函数/别名时无法直接启动；可用`HQAGENT_CODEX_PATH`或`HQAGENT_CLAUDE_PATH`指定真实可执行文件。Claude当前适配只开放只读工具。

验收细节与尚未完成项见[联合集成记录](../../.hqagent/reviews/N0-joint-integration.md)。
