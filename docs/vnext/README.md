本目录是下一阶段的设计基线，接口均为拟定，尚未进入 `packages/protocol` 的正式冻结或代码实现。最新方向是“保留底座、先做本地多场景角色对话试用，再接手机远程”。本目录不代表已有安装包、跨平台或远程运行能力通过验收。

“本地版/离线版”指不依赖自建 Hub Server、中转服务和手机网络；使用云模型的 Claude/Codex 仍需要联网。完全断网运行需另行具备本地模型及完整本地工具链，不作为此阶段承诺。

阅读顺序：

当前已完成前后端代码集成；开始试用请先看[本地试用启动](本地试用启动.md)，验收边界见[联合集成记录](../../.hqagent/reviews/N0-joint-integration.md)。当前工作目录为`HQAgent-Hub-worktrees/vnext-integration`，分支`integration/phase1`。

1. [技术方案](技术方案.md)：产品范围、技术选型、职责、数据和核心流程。
2. [接口与插件协议](接口与插件协议.md)：命令、事件、插件、会话及产物契约草案。
3. [实施与验收](实施与验收.md)：迁移步骤、工作包、验收场景及开工顺序。
4. [现状评审](../../.hqagent/reviews/2026-09-24-architecture-review.md)：代码证据和上一轮实际验证结果。

关联原则：

- 现有代码以 `integration/phase1` 及其已说明的工作区修改为审查基线，不能只看 main 推断完成度。
- 旧 [施工方案](../施工方案.md) 等文件保留为既有设计与实施记录；vNext 的优先级和目标以本目录为准。现行代码权限、协议版本及生成规则未因文档而改变。
- `AGENTS.md` 的代码路径所有权和独立 worktree 约束仍执行；本轮只新增架构文档，由主代理统一维护，不修改冻结协议或业务源码。
- 接口进入实现前，由协议负责人在唯一的 `packages/protocol` 定义并生成 DTO。本目录示例是设计样例，不能作为另一个手写生产 DTO 来源。
- 示例中的模型名、能力、任务 ID、URL 和状态是示意；可用模型与真实执行结果由目标节点探测并验证。
- 旧 D38 仍保持：非 Git 目录可以只读分析，Agent 写任务必须有隔离工作区。空目录初始化走受控 Bootstrap 操作，详见技术方案，不允许借此向任意已有目录就地写入。

当前方向：Vue/TypeScript 本地对话界面 + Python Worker + SQLite + 内置 Agent 插件。Python 单体服务端、设备配对和公网 HTTPS/WSS 留到本地试用通过后；桌面壳与 OTA 不作为前置。

下一实施入口是 [N0-A 可靠性 → N0-B 本地角色对话试用版](实施与验收.md)。N0-A 是内部工程步骤，N0-A+N0-B 共同形成首个可用版本；验收重点是场景配置、真实对话执行和连续任务效果。
