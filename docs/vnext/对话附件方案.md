本文是设计基线，不是已实现功能。产品定位、电脑唯一写入、服务器完整副本、忙碌锁、离线直接失败、可见性等规则沿用 [手机远程接入方案](手机远程接入方案.md) §11，本文只补附件相关部分。

**开工时机**：等「设备管理 + 全量接口规范」这一轮（协议 0.8.0）上线之后再开工。附件接口从一开始就按那一轮定下的规范设计：写进 OpenAPI 和 `api-guide.md`、进错误码总表、带 requestId，鉴权规则一致。

## 1. 方案选择

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| **服务器中转存储** | **采用** | 符合「电脑唯一写入、服务器完整副本」：历史里的附件两端都能看到，电脑重启、断线后也能重新下载 |
| 服务器只转发不存储 | 不采用 | 要求电脑当时在线；违背完整历史的决定；大文件走长连接会阻塞消息、忙碌快照这些实时信号 |
| 手机直连电脑 | 不采用 | 需要内网穿透或 P2P，与「电脑只主动向外连接」的设计冲突 |

## 2. 数据流

### 2.1 手机 → 电脑（第一期核心）

```
手机选文件
  → 上传到服务器（流式写盘，返回 attachmentId、sha256、size、mime）
  → 发消息时 RemoteSendMessageInput 只带附件 ID 列表
  → 服务器校验归属、状态与配额，在命令中附上附件清单（ID/文件名/类型/大小/hash），不带文件内容
  → Worker 接单（沿用 30 秒送达与 grant 规则，清单不影响送达时限）
  → Worker 用设备凭据经 HTTPS 下载，逐个校验 sha256 与大小
  → 存到 %LOCALAPPDATA%\HQAgent-Hub\attachments\<对话>\
  → 交给 Agent：图片走 CLI 的图片输入；文件把本地路径写进提示词，必要时复制到 Agent 可读位置
```

- **线路上只传清单。** 长连接帧和 30 秒窗口都与文件大小无关。
- **下载放在接单之后、Agent 启动之前**：
  - 这段时间对话处于忙碌状态；
  - 下载失败时这一轮明确失败，错误码写进错误码总表，提示「附件下载失败」，不会卡住；
  - 下载受重试上限和总超时约束，不会无限重试。
- **本地存储**：
  - 放在用户数据目录，不写安装目录（AGENTS.md §7）；
  - 按对话分目录；
  - 删除对话时一起清理。

### 2.2 电脑 → 手机

- 电脑本机发消息时附带的文件：
  - 本机保存；
  - 按现有同步规则上传到服务器，走同步事件加附件上传；
  - 手机端可以看到缩略图，并下载原文件。
- 同步总开关关闭时不上传；关闭时服务器上已有的附件，与对话正文一起删除。

## 3. 限制值（第一期，用户已确认）

| 项 | 限制 |
| --- | --- |
| 图片 | jpg / png / webp / gif，每张 ≤ 10MB |
| 文档与代码文件 | pdf / txt / md / json / 常见源码后缀，每个 ≤ 20MB |
| 每条消息附件数 | ≤ 5 |
| 每个账号总配额 | 5GB，超出返回配额错误，不静默丢弃 |
| 未发送附件 | 上传后 24 小时内未随消息发出，自动清理 |
| 服务端内存 | 上传和下载一律流式处理，不整文件读入内存（serverD 只有 2G 内存） |

类型以内容检测为准，不只看后缀。不在白名单里的类型直接拒绝。

## 4. Agent 能力

- 并非每个 Agent 都能处理图片。电脑上报的目录（catalog）中，要标明每个场景的各角色能否接收图片。
- 手机选了图片，而目标场景有角色不支持图片时，**发送前**就提示，不能发出去再失败。
- 文件（非图片）一律以本地路径的方式交给 Agent，不依赖 Agent 的特殊能力。

## 5. 删除、可见性与同步

附件跟随所属对话，沿用 §11 的所有规则：

- 删除对话、关闭同步总开关、删除设备时，服务器上的附件一起真删除，要有测试直接查存储证明。
- `pc_only` 对话的附件对手机隐藏，直接用 ID 访问返回 NOT_FOUND；`mobile_only` 同理，只影响显示。
- 暂停远程（D50）时不能上传新附件、不能发消息；已有附件的下载不受影响。
- 电脑离线时发送直接失败。已上传未发送的附件保留，由 24 小时清理兜底。

## 6. 安全

- 所有上传和下载都要鉴权：
  - 浏览器用 Cookie + CSRF；
  - Worker 用设备凭据；
  - API 令牌能否访问附件，按接口规范单独定义权限范围，例如 `attachments:read`。第一期可以先不开放。
- 服务器只存储、不执行、不解析文件内容，缩略图生成除外。
- 下载响应一律带 `Content-Disposition: attachment` 和 `X-Content-Type-Options: nosniff`，不在页面中直接渲染 HTML、SVG 这类可能含脚本的内容。图片预览只用服务端生成的缩略图。
- 文件名做规范化，防止路径穿越。Hub 落盘时不使用原始文件名作为路径。
- 附件内容、下载链接、凭据不进入日志。日志只记附件 ID、大小、hash 前缀和 requestId。

## 7. 存储

- 第一期：serverD 本地磁盘 `/var/lib/hqremote/blobs/`，按 sha256 内容寻址并去重，引用计数决定真删除时机。当前剩余磁盘约 36G。
- 存储层抽象成接口（写入流、读取流、删除、存在性检查），第二期切换到阿里云 OSS 时只替换实现。
- 备份：沿用服务端 Backup 流程，附件目录单独备份，与数据库快照记录对应关系。

### 7.1 为 OSS 预留的接入方式（用户 2026-09-30 要求，第一期必须做到）

第一期不买 OSS，但以后切换时只加一个存储实现、改配置，不动业务代码、协议和客户端。第一期代码要满足：

1. **存储接口唯一入口**：业务代码只通过 BlobStore 接口（写入流、提交、读取流、删除、存在性、放弃）访问附件与缩略图。本地磁盘路径、`open()`、`os.path` 只允许出现在本地实现里。
2. **配置选择实现**：用环境变量选择存储后端（例如 `HQREMOTE_BLOB_BACKEND=local`），默认 local；启动时校验配置，未知值直接拒绝启动。
3. **对象键与云存储兼容**：按 sha256 生成对象键（例如 `blobs/ab/cd/<sha256>`、`thumbs/<sha256>.png`），键里不含本机路径、账号或文件名，可以原样用作 OSS 的 object key。
4. **通用契约测试**：同一套存储测试可以对任意实现运行（写入、校验失败回滚、并发同 hash、删除、读者句柄、崩溃恢复），以后 OSS 实现跑通这套测试就算接入完成。
5. **不依赖本地文件特性**：不用硬链接、`sendfile` 或文件锁表达业务语义；引用计数、配额、删除栅栏都在数据库里，不靠文件系统。
6. **下载出口单独封装**：下载响应由一个出口函数生成。第二期要改成「服务器返回短期签名链接，客户端直连 OSS」时只改这一处；因为要改客户端行为（例如 Worker 接受签名 URL），届时再做一次协议修订。

第二期接 OSS 的工作量预估：实现 OSS 版 BlobStore、跑通契约测试、配置切换、把存量本地附件迁移到 OSS。需要直传直下时再加一次协议修订。

## 8. 协议影响

- 命令信封和同步帧新增附件清单字段。按现有严格校验规则，需要升 wireRevision 到 **4**（3 已被 R3 原生会话占用），服务端同时支持 [1,2,3,4]；电脑端 Hub 升级后才能收发附件。
- 新增 HTTP 接口：
  - 浏览器：上传、查询、删除未发送附件、下载原文件、获取缩略图；
  - Worker：下载附件、上传电脑端附件。
- 全部接口按 0.8.0 的接口规范：写进 OpenAPI、`api-guide.md`、错误码总表，带 requestId，给出鉴权说明。
- 新增错误码（名称以协议冻结为准）：附件过大、类型不支持、数量超限、配额不足、附件不存在或已清理、hash 校验失败、Agent 不支持图片。

## 9. 两期范围

| 期 | 内容 | 出口 |
| --- | --- | --- |
| **第一期（R1.6）** | 手机发图片和文件给电脑，Agent 能分析；电脑端附件同步到手机展示和下载；限额、24 小时清理、删除联动、可见性过滤；Agent 图片能力提示 | §10 验收通过 |
| **第二期** | Agent 产出的文件（报告、截图、补丁、APK 等）回传手机下载；断点续传；存储切换到阿里云 OSS，预签名直传直下 | 另行验收 |

## 10. 第一期验收

1. 手机发一张截图，问「图里是什么报错」，电脑上的 Agent 能正确描述；电脑工作台同步显示这张图。
2. 手机发一个 20MB 以内的 pdf 或源码文件，Agent 能读取并回答其中的内容。
3. 超过大小、类型不在白名单、单条超过 5 个、超出账号配额时，上传前或上传时就给出明确提示。
4. 目标 Agent 不支持图片时，发送前提示，不会发出去再失败。
5. 电脑在下载附件时被强杀：重启后这一轮明确失败或可重试，对话不会一直忙碌。
6. 电脑本机发的附件，手机上能看到缩略图并下载原文件。
7. 删除对话、关闭同步总开关、删除设备后，服务器存储里查不到对应附件。`pc_only` 对话的附件，手机上用直接 ID 访问返回 NOT_FOUND。
8. 上传后没有发送的附件，24 小时后被清理。
9. 上传 20MB 文件时，服务端内存没有明显上涨，证明是流式处理。
10. 日志中查不到附件内容、下载链接和凭据；每个请求都能用 requestId 定位。
