## 1. 本轮交付和基线

本轮只形成 [技术方案](技术方案.md)、[协议草案](接口与插件协议.md) 及本清单，不实施业务重构、远程部署或协议生成。前次现状评审见 [评审记录](../../.hqagent/reviews/2026-09-24-architecture-review.md)。

代码审查参考点为 `integration/phase1` 的 `0824cbbbd97b69efaf53ee0312f718d7ab79c86a`，同时参考评审时四个既有未提交文件；这不是可复现的施工基线。本轮不自动 commit/stash/reset/合并这些修改。进入实施前必须确认归属，并以明确提交 SHA，或 SHA + 已存档且含 SHA-256 的 patch 建立可复现输入；不能仅写“使用当前四个修改文件”。

## 2. 实施顺序与出口

### N0-A：修复现有本地真实执行链

目标：先让已存在的操作兑现语义，不改编程语言，不引入云依赖。

1. 创建任务和控制动作使用真实 TaskService 的命令去重与事务边界；补生产应用服务测试，不能只测 TransactionalTaskPort。
2. Task/Node 终态只有一个写入位置；按真实 AgentResult、流终态和必需产物判断结果，不因没有路径越界就算成功。
3. 把审批事件创建、数据库记录、回应、时效、原生请求回送和取消接通；修正 decide/respond 接线。
4. 续接时检查 AdapterFailure，重建执行规格和事件泵；保存指令，推动 resume/retry/append，而非仅改显示状态。
5. 取消确认原生 turn/受管进程树停止；Hub 重启先核实非终态执行，不能把找不到内存句柄视作没有运行。

出口：真实生产服务通过 E01–E07。允许受控 Fake Runtime 模拟崩溃/延迟，但必须经过真实 Composition/TaskService/Repository；另外至少完成一次真实 CLI 只读及一次隔离文件修改验收。

### N0-B：本地多场景角色对话试用版

N0-A是内部修复阶段，N0-A+N0-B才是用户可试用的第一版。优先验证本机Agent分工和连续对话的实际效果。

1. 复用Vue组件，增加本地聊天与进度入口，选择项目/任务/已有会话后直接输入描述。对接真实Worker，不能以Mock演示验收。
2. 提供代码分析、需求规划、开发修复三个场景模板，支持编辑角色职责、Agent、model/effort；选配规划/复核，不强制所有任务多人协作。
3. 增加本机Conversation/Message、Run与执行快照；任务和会话映射由Worker内嵌服务保存，v1→v2映射明确。
4. 通过内置注册表包装Claude/Codex；暂不建设插件管理市场或额外Model Provider。目录已明确时跳过前置识别模型。
5. 完成真实模型配置传递、下一轮配置生效、流式结果、续接、失败提示、审批和取消；路径/进程管理通过平台接口隔离。
6. 只读场景不强制Git；写场景仍在隔离worktree中验证。方案场景只交付方案，后续用户要求实施时再创建实施Run。

出口：L01–L05本地试用验收通过；用户能够独立完成“选场景→配置角色→对话执行→查看结果→继续”的完整流程。过程中不需要VPS、域名、云端账号或手机。

### N1：本地试用通过后的最小远程闭环

1. 单所有者服务端、设备配对、Worker 主动 WSS、持久 Command/Outbox/事件投影。
2. Web 生产 RemoteGateway、任务/对话界面、移动布局、进度与继续/暂停/取消/审批。
3. 手机断线、Worker 断线、重复命令、事件缺口、重启状态核对。
4. 原生会话发现/读取/导入按能力开放，外部活跃会话只展示可确认的状态。

出口：Q20 只读代码梳理 → 返回结果 → 同任务追加要求 → 正确续接；关闭手机不终止任务，断线不重复派发。

### N2：截图修复与 APK 交付

1. 附件上传、内容校验、视觉能力路由、原图和分析关联。
2. 在N0已有规划/执行模板上增加截图修复和交付步骤，规划者通过Worker派工工具提交受约束任务，保存真实交接资料。
3. 修复输出关联 CodeSnapshot；构建 profile 固定 variant、工具链和签名引用。
4. 内置 Android Builder 与 Artifact Uploader 插件；构建和上传以明确输入产物为边界。
5. 发布授权与实际目标/hash绑定，校验下载，记录用户现场反馈。

出口：用户先收到修复报告；再发打包指令后生成 APK 并上传；重复回执不重复发布；能追溯 APK 到该次修复。

### N3：平台与安装交付

三平台分别验证安装/发现/目录/取消/恢复；只在实际通过的平台上标记支持。可选桌面壳与 OTA 独立回归，不扩大 N1/N2 的关键路径。

## 3. 工作包与文件所有权建议

以下是后续施工分工，与产品运行中的 planner/executor 角色不同。每条实现线在独立 worktree 工作；同时最多三个 Codex（含主代理），紧密依赖协议的部分先串行冻结。

| 包 | 范围 | 可写目录（正式开工时指定） | 依赖 |
| --- | --- | --- | --- |
| V0 协议与集成 | 新旧映射、唯一 Schema/DTO、公共错误、组合入口与根配置 | `packages/protocol/**`、`scripts/protocol/**`、`.hqagent/**`、共享根与 Composition Root | 无；串行协调 |
| V1 Worker 可靠性 | TaskEngine、RunSupervisor、Inbox/Outbox、审批与恢复 | 原 W1 runtime/storage/api 与原 W3 orchestrator/security 中明确分配的路径 | V0 最小契约；不能与原包同时写同一路径 |
| V2 Agent 与插件宿主 | 原 Adapter 修复、模型/历史/附件接口、插件注册/受管进程 | `apps/hub/adapters/**`；拟新增 `apps/hub/plugins/**`、`apps/hub/platform/**` | V0；与 V1 接口固定后可并行 |
| V3 服务端 | 账号、设备、命令队列、事件投影、附件入口 | 拟新增 `apps/server/**` | V0 远程协议 |
| V4 Web | N0本地聊天/场景角色；N1再补RemoteGateway/移动布局，N2补附件 | 现有 `apps/desktop/src/**` 的指定路径；共享组件暂不机械搬目录 | V0本地契约优先；不等待服务端 |
| V5 交付能力 | Builder、Uploader、产物溯源与环境检查 | 拟新增 `plugins/android-builder/**`、`plugins/artifact-uploader/**` | V0 插件/Artifact契约、V1 执行基础 |
| V6 验收/打包 | 故障场景、真 CLI、跨平台安装 | `scripts/e2e/**`、`build/**`，测试路径按所属模块分配 | 对应阶段可运行产物 |

第一批做V0+V1/V2的N0-A必要修复；本地接口明确后V4接入N0-B聊天/角色界面。V3服务端暂不启动，不同时启动六条功能线。现有AGENTS路径规则仍有效，新目录/角色所有权在正式开工任务书中登记。

## 4. 从旧代码到新结构的具体映射

| 现有位置 | 处理方式 |
| --- | --- |
| `runtime/tasks.py` | 拆出命令处理/执行推进；先修真实应用服务，逐步映射 Task/Run/Attempt |
| `runtime/composition.py` | 统一装配插件注册表、Supervisor、审批 Broker；保持唯一组装入口 |
| `orchestrator/runtime.py` | 返回节点级结果；不与应用层同时写整个 Task 终态 |
| `orchestrator/role_resolver.py` | 保留规则，补 Runtime/Model 的能力交集与配置快照 |
| `orchestrator/sessions.py` | 检查恢复结果、映射原生历史、保留谱系和明确会话锁 |
| `adapters/*` | 保留原生协议实现，通过 Mapper 暴露 vNext 能力；逐项真机验证 |
| `storage/events.py` 与 SQLite | 保留 seq，补原子 Outbox/Inbox、workerStoreId 与恢复核对 |
| `security/worktrees.py` | 保留隔离；读任务不强制 Git；构建继承明确修复快照 |
| `desktop/src/shared/api` | 保留UiGateway，先补生产本地聊天Gateway；N1再新增RemoteGateway；Mock仅开发/测试 |
| Tauri、Update Agent、Updater | 保留；主干验收暂不依赖完整升级链 |

数据库采用增量迁移和迁移前一致性备份。无法确定原生会话、工作树或历史执行结果的旧记录标为 legacy/unknown，不伪造成功或可恢复状态。

## 5. 可复现验收矩阵

以下为待实现验收场景，不是本轮已通过测试。

### 本地试用版出口

| ID | 场景 | 可观察通过条件 |
| --- | --- | --- |
| L01 | 不配置Hub Server/VPS，只启动本机Worker和Web | 可选择项目与Agent，真实运行任务；本地持久化不依赖云服务 |
| L02 | 分别用分析、规划、开发修复场景提交任务 | 按角色职责执行；分析只读，规划不擅自实施；修复给出真实改动/验证 |
| L03 | 配置Claude规划+Codex执行，再配置Codex承担两个独立角色 | 角色指令、权限、具体模型与会话分离可追溯；不支持的配置明确报错 |
| L04 | 同一任务连续对话，关闭页面后重开，再重启Worker | 至少一种Runtime通过真实续接；其他Runtime的缺口显式展示；消息/任务不丢失、不重复派发 |
| L05 | 同一隔离基线分别试单Agent和分工方案 | 记录结果质量、实际耗时、调用次数和多余改动；有用量才记录成本，不凭空宣称节省 |

N0验收不要求完全断网调用云模型。连接模型所需的网络/账号与是否部署自建云端是两个条件。

### 可靠性与后续扩展验收

| ID | 场景 | 可观察通过条件 |
| --- | --- | --- |
| E01 | 同一请求 key 连续提交三次，再用同 key 改内容 | 一条 Command/Run，一次启动；改内容返回 409 |
| E02 | 真 TaskService 收到 AgentResult=failed/blocked，或异常 EOF | 不显示 succeeded；错误、Attempt 和事件一致 |
| E03 | Agent请求审批，本地界面批准、拒绝、过期、重复回应；N1再验证手机 | 请求先落库；只向对应原生请求消费有效决定；过期/变化参数不放行 |
| E04 | 任务结束后关闭 Hub，再按明确 session ID 继续 | 能恢复则新轮次有输出；不能恢复则明确失败，不假标 ACTIVE |
| E05 | 运行中追加一条要求，再取消/暂停另一轮 | 追加不改当前输入；暂停到边界；控制命令指向正确 Run |
| E06 | 取消时子命令延迟退出，或拒绝退出 | 先 cancel_requested；确认停止才 cancelled；不明结果进入 recovery_required |
| E07 | 在启动进程前后、写状态前后注入崩溃 | 重启先核对；写入/发布不盲目再跑；旧 Attempt 保留 |
| E08 | 手机离线重连，Worker 同一事件批次重复上报 | 浏览器不重复消息；服务端只确认连续已落库序号 |
| E09 | Worker 离线后现有任务继续，手机再发新任务 | 已接任务按授权继续，新命令排队；其他设备不抢跑 |
| E10 | 同一个外部会话在两个业务入口同时继续 | 最多一个活跃 Attempt；另一条明确排队或拒绝 |
| E11 | 导入独立 CLI 的历史，会话仍活跃/状态未知 | 可读历史，不无条件启动第二个写进程 |
| E12 | 指定不支持的模型/effort，或运行中修改默认配置 | 不静默替换；当前快照不变；后续按新配置重新验证 |
| E13 | 只读非 Git 目录，空目录新建项目，非空目录初始化 | 只读可执行；新建须受控 bootstrap；非空目录不会自动提交/覆盖 |
| E14 | 图片未上传完、hash不符、运行时不支持图像 | Artifact 不进入 ready/执行；能力缺口可见；原图不被丢弃 |
| E15 | 修复后上传一个旧 APK，或构建期间工作树被改 | 来源验证失败；不能把旧产物标成此轮修复的交付 |
| E16 | APK 上传完成但回应丢失，随后重连重试 | 查目的端 hash；同发布操作不重复生成新发布；能返回原结果 |
| E17 | 添加受信样例插件、禁用插件、升级执行中插件 | 无需改TaskEngine接入；缺能力明确；旧Attempt版本不被替换 |
| E18 | Windows/macOS/Linux 分别启动、发现CLI、运行与取消 | 各平台记录工具版本和结果；未验收平台不冒充已支持 |

E17 样例插件只生成固定文本 Artifact，不执行任意 shell，用于证明协议而不是扩大权限。

## 6. 测试与验收责任

- 模块单测归模块负责人；主代理复用可信结果，不重复跑同一套测试。
- 集成负责人必须测试实际装配后的服务与数据库，尤其是现有 fakes 曾掩盖的 TaskService 接线。
- 真 CLI 验收在临时隔离仓库执行；不默认把 Q20 源码当成破坏性测试夹具。
- 首个Q20场景在本机只读梳理RTK，再通过对话追加要求；写入效果优先使用隔离样例仓库比较。手机、打包和上传后续接入。
- 现场硬件功能由用户安装验证，报告区分编译、自动测试和现场验证状态。
- 文档/schema校验不能代替真实产品验收；模块测试全绿不能代替手机断线和服务重启测试。

已存在的基线命令（在 integration 对应目录执行）：

```powershell
# apps/hub
../../.venv/Scripts/python.exe -B -m pytest -q -p no:cacheprovider

# 仓库根
pnpm --filter @hqagent/desktop test
pnpm --filter @hqagent/desktop typecheck
```

新增E01–E18与L01–L05的自动化或可复现操作入口由实施工作包交付；本文不提供尚不存在的“验收脚本命令”冒充可执行。

## 7. 第一个实施任务书

```text
任务：N0-A 本地真实执行链修复。

目标：使真实 TaskService 的去重、结果终态、审批、追加/重试/恢复和取消可验证。
基线：先核对 integration/phase1 与既有未提交修改，建立明确的独立工作目录。
必读：vNext 技术方案、协议草案、现状评审、现有 AGENTS 和所属路径规则。

先做：
1. 用实际 Composition/Repository 复现并修复相同请求创建多任务。
2. 消除 Node 与 Task 的双重终态写入，保证 failed/blocked 不显示成功。
3. 接通 ApprovalBroker 与真实 Adapter 请求，修复 decide/respond 错位。
4. 实现有持久化输入和输出流的继续/重试，处理重启后缺失内存态。
5. 用受管执行状态确认取消结果。

暂不做：云部署、手机页面、插件市场、全量OTA、其他产品迁移。
约束：不放宽现有授权/路径边界，不用 latest 猜会话，不把失败改为成功降级。
交付：小范围代码变更、真实命令输出、E01–E07 的复现与结果、未解阻断。
验收：旧测试保留，通过真实应用服务新增验收；真实CLI验证单独记录。
```

## 8. 仍待实施验证的事实
