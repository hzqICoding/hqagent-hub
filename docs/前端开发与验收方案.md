## 1. 文档目的

本文档是 HQAgent-Hub 第一期桌面前端的开工与验收依据。前端负责人在不等待 Local Hub、Agent Adapter 和 OTA 真实接口完成的情况下，应能依靠本文档、类型契约和 Mock 场景独立完成页面开发、交互、自测和交付。

本文档覆盖：

- 产品视觉方向和参考样例取舍。
- 系统、浅色、深色模式及多配色主题架构。
- 桌面端信息架构、页面、组件和交互规范。
- 前端与 Local Hub、Tauri、Update Agent 的边界。
- Mock/真实数据双通道设计。
- 任务拆分、里程碑、测试矩阵和最终验收证据。

本文档不要求前端负责人实现：

- Claude、Codex、Gemini、Antigravity 等 Agent 的进程控制。
- Local Hub 的任务编排、权限执行、Session 持久化和数据库逻辑。
- Go Update Agent/Updater 的下载、验签和安装逻辑。
- VPS Control Plane、支付、授权和手机 PWA。

## 2. 已确认结论

1. 桌面前端可以作为独立工作包交给单独的开发者或 Gemini/Antigravity 执行。
2. 技术基线为 `Tauri 2 + Vue 3 + TypeScript + Vite`。
3. 第一期默认外观为 `mode=system`、`palette=hq-blue`、`density=comfortable`。
4. 外观模式与配色方案必须解耦：用户可独立选择系统/浅色/深色，也可切换蓝色、紫色、青色、绿色等配色。
5. 所有业务组件只能使用语义化 Design Token，禁止在页面组件内直接写固定背景色、文字色或厂商品牌色。
6. 前端必须同时支持 `MockGateway` 和 `LocalHubGateway`，通过环境配置切换，不允许在页面中判断 Mock/真实模式。
7. UI 不得把职责与 Agent 厂商绑定；角色颜色、Agent 图标、任务状态颜色分别管理。
8. 第一期以专业、紧凑、可信的“AI 团队控制中心”为主，不做纯聊天软件，也不采用大面积霓虹、玻璃拟态或展示型 landing page 风格。
9. P0 使用原生窗口标题栏，先完成 Windows 可用性和可访问性验收，同时保持 macOS 兼容预留；自定义标题栏作为 P1，不阻塞第一期。
10. 桌面前端和 OTA 同期建设，设置页、更新状态、下载进度、升级审批和任务排空提示均属于第一期。
11. Phase 1 的真实联调只要求 Claude 与 Codex；界面和 Mock 必须保持供应商无关，可展示 Antigravity/Gemini 等实例，但这些 Adapter 的真实接入属于 Phase 1.1，不阻塞前端一期验收。Cloud/手机状态在 Phase 1 显示为“未启用”或 Mock，不依赖 VPS。

该项目由 57 个独立静态 HTML/Tailwind CDN 风格示例组成，适合提取配色、排版和布局原则，但不是可直接用于生产的组件库，原因包括：

- 每个页面相互独立，没有统一 Design Token。

- `07-dark-mode-oled.html`：纯黑和荧光绿对比过强，适合作为后续 `oled` 特殊主题，不适合作为默认深色主题。

- Cyberpunk/HUD/Sci-Fi：适合展示，不适合长时间开发和企业用户。
- Neumorphism/Claymorphism：交互边界和禁用态不够明确。
- Gen Z Chaos/Vaporwave/Y2K：与工具型产品的可信度和信息密度目标不符。

## 4. 用户与核心场景

### 4.1 第一类用户：个人开发者

- 已安装两个或多个本地 AI Agent。
- 希望配置“谁负责架构、谁负责前端、谁负责实现和审核”。
- 需要持续观察任务、审批风险操作、查看产物并恢复 Session。

### 4.2 第二类用户：多项目开发者

- 不同项目使用不同 Team Profile。
- 需要快速切换项目、团队模板和任务上下文。
- 关注 Agent 可用性、版本、登录状态、消耗和失败原因。

### 4.3 第三类用户：远程控制用户

- 通过手机/VPS 下达任务。
- 桌面端需要清楚标识任务来源、远程审批和设备连接状态。
- 第一期桌面端只预留展示和事件入口，完整手机端不在本工作包内。

## 5. 前端总体架构

```text
Vue Pages / Domain Components
              │
              ▼
      Application Services
              │
        Pinia Domain Stores
              │
              ▼
         UiGateway Port
        ┌─────┴───────────┐
        ▼                 ▼
 MockGateway       LocalHubGateway
 JSON Fixtures     HTTP + WebSocket
                          │
                          ▼
                     Local Hub

独立平台能力：

ThemeEngine ────── Browser/System Theme
DesktopBridge ──── Tauri Window/Tray/Dialog
UpdateViewModel ── Local Hub 代理后的 Update State
```

### 5.1 分层职责

| 层 | 职责 | 禁止事项 |
| --- | --- | --- |
| Page | 路由页面、布局组合、页面级加载与错误状态 | 直接调用 HTTP、WebSocket 或 Tauri invoke |
| Feature | 团队编辑、任务创建、审批、更新等业务交互 | 直接使用 Claude/Codex/Gemini 厂商判断 |
| Entity | Agent、Role、Task、Session 等领域展示组件 | 修改全局状态或发起网络请求 |
| Store | 状态、派生数据、用户操作编排 | 放置 DOM、颜色和具体组件逻辑 |
| Service | 调用 Gateway、事件转换、错误映射 | 引用 Vue 页面组件 |
| Gateway | Mock 或 Local Hub 通信 | 把协议原始字段直接泄漏到页面 |
| Shared UI | 通用组件和 Design Token | 包含 HQAgent 业务规则 |
| Desktop Bridge | 文件选择、系统通知、窗口和托盘 | 执行 Agent 业务编排 |

### 5.2 核心约束

- 页面只能依赖统一的 `UiGateway` 接口。
- `MockGateway` 和 `LocalHubGateway` 必须返回完全相同的领域类型。
- `UiGateway`、ViewModel 和 Application Service 由前端手写；`ApiEnvelope`、`HubEvent`、状态枚举和网络 DTO 从 `packages/protocol/generated/ts` 导入。
- Vue 只连接 Local Hub，不读取或直连 Update Agent Endpoint。
- HTTP 使用 Tauri 提供的启动期 Bearer Token；WebSocket 先以 Bearer 调用 `/api/v1/auth/ws-ticket`，再用一次性 Ticket 建立连接。
- WebSocket 原始事件先经过 `EventMapper`，再进入 Store。
- 所有可重放事件携带 `eventId` 和单调递增 `seq`。
- 所有状态枚举都有未知值兜底，避免后端升级导致白屏。
- 前端不保存 Agent Token、API Key、SSH Key 或厂商登录凭据。
- 页面不得调用 `callClaude()`、`callCodex()`、`callGemini()` 等厂商绑定函数。

## 6. 推荐前端技术栈

| 分类 | 选择 | 用途 |
| --- | --- | --- |
| 框架 | Vue 3 + TypeScript | 页面与组件 |
| 构建 | Vite | 开发、构建和 Mock 模式 |
| 桌面容器 | Tauri 2 | Windows/macOS 桌面壳 |
| 路由 | Vue Router | 页面路由和权限守卫 |
| 状态 | Pinia | 领域状态、连接状态和设置 |
| 样式 | CSS Variables + Tailwind CSS | 语义 Token、多主题和布局工具类 |
| 图标 | Lucide Vue | 一致的线性图标体系 |
| 图表 | ECharts，按页面异步加载 | 任务、Agent 和统计图表 |
| 协议校验 | Zod | Mock/Local Hub 响应运行时校验 |
| 单元测试 | Vitest + Vue Test Utils | Store、Service 和组件测试 |
| E2E | Playwright | 页面流程、主题切换和视觉快照 |
| 国际化 | vue-i18n | P0 简体中文，预留英文 |

约束：

- 依赖版本必须锁定在 `pnpm-lock.yaml`。
- 不允许运行时依赖 Google Fonts、Tailwind CDN 或其他公共 CDN。
- 字体、图标和必要资源必须随安装包离线提供。
- 不在第一期同时引入两套完整 UI 组件库。
- Headless 组件可用于无障碍交互，但视觉必须由 HQAgent Design Token 控制。

## 8. 主题系统架构

### 8.1 配置模型

主题不是一个简单的 `isDark` 布尔值。必须拆成模式、配色、密度、对比度、动效和字号：

```ts
export type ThemeMode = 'system' | 'light' | 'dark'
export type ResolvedThemeMode = 'light' | 'dark'
export type ThemePalette =
  | 'hq-blue'
  | 'ai-violet'
  | 'tech-cyan'
  | 'ops-emerald'
export type UiDensity = 'comfortable' | 'compact'
export type ContrastMode = 'normal' | 'high'

export interface AppearanceSettings {
  mode: ThemeMode
  palette: ThemePalette
  density: UiDensity
  contrast: ContrastMode
  reduceMotion: boolean | 'system'
  fontScale: 0.9 | 1 | 1.1 | 1.2
}

export const defaultAppearance: AppearanceSettings = {
  mode: 'system',
  palette: 'hq-blue',
  density: 'comfortable',
  contrast: 'normal',
  reduceMotion: 'system',
  fontScale: 1,
}
```

### 8.2 DOM 表达

ThemeEngine 解析后只在根节点设置属性：

```html
<html
  data-theme-mode="dark"
  data-theme-source="system"
  data-theme-palette="hq-blue"
  data-density="comfortable"
  data-contrast="normal"
  data-reduce-motion="false"
>
```

组件只能读取 CSS Variables，不允许根据 `isDark` 在模板中维护两套 class。

### 8.3 启动顺序与无闪烁要求

1. `index.html` 中的最小启动脚本读取无敏感信息的外观缓存。
2. 若 `mode=system`，立即读取 `prefers-color-scheme`。
3. 在加载 Vue Bundle 之前写入 `data-theme-*` 属性。
4. Vue 启动后从 Local Hub 读取完整用户设置并校正缓存。
5. 当模式为 `system` 时监听操作系统主题变化并实时切换。
6. 同步通知 Desktop Bridge 调整原生窗口外观；具体 Tauri API 封装在 Bridge 内。
7. 用户设置更新后写入 Local Hub，同时刷新本地启动缓存。

外观缓存只允许包含主题 ID、密度、字号等 UI 设置，不得包含 Token、项目路径、用户信息和 Agent 凭据。

设置作用域默认为“当前设备”：Local Hub 中的设备级设置是权威来源，本地启动缓存只用于消除首屏闪烁。后续接入云端同步时，云端偏好只能作为新设备初始值，当前设备的显式选择优先，避免一台电脑切换主题后强制改变其他电脑。

### 8.4 Token 分层

```text
Primitive Token
  原始色阶、间距、字号、圆角
        ↓
Semantic Token
  bg-app、bg-panel、text-primary、border-default、action-primary
        ↓
Component Token
  sidebar-bg、button-primary-bg、task-card-border、log-row-bg
        ↓
Domain Token
  task-running、agent-offline、role-architect、approval-danger
```

页面只能使用 Semantic/Component/Domain Token。Primitive Token 不得直接出现在业务页面。

### 8.7 配色方案

配色只改变品牌强调、主操作、焦点和选中态，不改变成功/警告/错误语义。

| --- | --- | --- | --- |

| `ai-violet` | `#6D28D9` | `#A78BFA` | 借鉴 AI-Native/Bento，突出 AI 产品感 |
| `tech-cyan` | `#0E7490` | `#22D3EE` | 技术感强，适合偏监控和运维用户 |

### 8.8 状态语义色

| 语义 | Light | Dark | 必须同时展示 |
| --- | --- | --- | --- |
| Success/Ready | `#15803D` | `#4ADE80` | 图标或文本 |
| Warning/Waiting | `#B45309` | `#FBBF24` | 图标或文本 |
| Danger/Failed | `#B91C1C` | `#F87171` | 图标或文本 |
| Info/Running | `#0369A1` | `#38BDF8` | 图标或文本 |
| Neutral/Offline | `#64748B` | `#94A3B8` | 图标或文本 |

禁止只使用红绿差异表达成功和失败，状态必须有图标、标签或文字。

上述核心正文、按钮文字和状态文字组合已经过初步对比度计算：最低核心正文组合为 4.76:1，四种主操作按钮白字均高于 5:1。组件实现后仍必须通过自动扫描和视觉验收，不能仅依赖本表。

### 8.9 Agent、角色和状态颜色分离

- Agent 厂商：使用图标和名称，例如 Claude、Codex、Gemini。
- 团队角色：使用独立角色色和角色标签。
- 运行状态：只使用固定语义色。

内置角色建议色：

| General Implementer | `--role-implementer` | Blue |

### 8.10 密度与字号

```text
comfortable：默认行高 36/40px，适合新用户和触控板
compact：表格和列表行高 28/32px，适合高信息密度用户
```

- 基础正文字号为 14px；设置页可切换 90%、100%、110%、120%。
- 正文不得低于缩放后的 12px。
- 日志和代码采用等宽字体，默认 12.5px/1.55。
- 主题、密度和字号切换不得要求重启应用。

### 8.11 OLED 和自定义主题预留

P1 可新增：

```ts
type SurfaceVariant = 'graphite' | 'oled'
```

OLED 只替换背景表面 Token，不修改功能组件。第一期不得为了 OLED 分叉组件或页面 CSS。

后续自定义主题应采用受控 JSON Schema，只允许覆盖公开 Token，不允许注入任意 CSS。

## 9. 视觉与交互规范

### 9.1 字体

```css
--font-sans: Inter, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: "JetBrains Mono", "Cascadia Code", Consolas, monospace;
```

- 不从公共 CDN 加载字体。
- 中文正文优先使用系统字体，避免安装包体积和字形缺失。
- ID、版本号、耗时、Token 数、命令和日志使用等宽字体。

### 9.2 间距和圆角

- 采用 4px 基础网格。
- 页面主间距：16px 或 20px。
- 卡片内边距：12px/16px。
- 普通组件圆角：6px。
- 卡片和弹窗圆角：8px/12px。
- 只有首次引导和首页重点卡片允许 16px 圆角。
- 不使用样例中 24px/32px 的大面积圆角作为全局风格。

### 9.3 阴影和边框

- 页面层级主要依靠背景层级与 1px 边框区分。
- 普通卡片只使用轻微阴影。
- Popover、Dialog、Command Palette 可使用中等阴影。
- 深色模式禁止大面积发光边框。

### 9.4 动效

- Hover/Focus：120ms。
- Drawer/Dialog：160–220ms。
- 页面切换不做大位移动画。
- 实时状态可使用轻微呼吸点，但同屏最多三个持续动画。
- 系统或用户要求减少动效时，取消非必要动画、平滑滚动和闪烁。

### 9.5 图标

- 默认使用 16px/18px 线性图标。
- 图标按钮必须有 Tooltip 和可访问名称。
- 不用 Emoji 作为正式功能图标。
- Agent 官方图标单独管理，不混入通用图标目录。

export interface HubEvent<T = unknown> {

- 大型日志数组不得无限保存在响应式 Store 中。
- 任务列表和任务详情分开缓存。
- Store 不直接显示 Toast，返回领域结果给页面/Application Service。
- WebSocket 重连采用退避策略，并显示离线状态；本地任务仍可继续时不得误报任务失败。

## 16. 性能与稳定性要求

- 首屏 Skeleton 在 300ms 后显示，避免短加载闪烁。
- 普通页面首次可交互目标不超过 2 秒；以打包后的 Tauri 环境验收。
- 10,000 条事件使用虚拟列表后滚动保持可用，不一次渲染全部 DOM。
- 高频事件按帧或 50–100ms 批量合并，不能每条事件触发全页面重算。
- ECharts 和 Markdown 高亮按页面异步加载。
- 路由页面采用懒加载。
- WebSocket 断线重连后不得重复显示事件、审批或任务。
- 用户切换主题、Palette、密度时不刷新页面、不丢当前路由和输入内容。
- 更新安装前进入维护模式，前端禁止再创建新任务，并持续显示 Task Drain 状态。

## 17. 安全要求

- Markdown 默认禁止任意 HTML；链接、图片和代码块经过安全处理。
- 外部链接必须经过统一 Bridge 打开并明确显示目标域名。
- 前端不直接执行 Shell 命令，不拼接命令字符串。
- 文件选择、打开目录、系统通知和剪贴板使用受控 Desktop Bridge。
- 不把 Token、Cookie、Agent 凭据、完整环境变量写入日志、Store 持久化或埋点。
- 审批卡片对命令、路径和参数进行等宽展示，不把不可见字符静默隐藏。
- UI 埋点使用事件白名单，禁止采集用户提示词、代码、文件内容、绝对项目路径和命令全文。
- 自定义主题只允许 Schema 中声明的 Token，禁止注入 `<style>` 或任意 CSS。

## 18. 可访问性要求

- 普通文本对比度至少 4.5:1；大文本和关键图形至少 3:1。
- 所有交互可通过键盘完成。
- `focus-visible` 清晰可见，不能仅依赖浏览器默认细线。
- Modal/Drawer 打开后正确管理焦点，关闭后返回触发元素。
- 图标按钮有可访问名称。
- 表单错误与具体字段关联，并提供文字原因。
- 颜色不作为唯一状态信号。
- 日志自动滚动允许暂停。
- 动画遵循 `prefers-reduced-motion` 和用户设置。
- 字号放大到 120% 后，主要页面不遮挡主要操作。

## 19. 国际化与文案

- P0 默认简体中文。
- 页面文案通过 i18n Key 使用，不在业务组件中散落字符串。
- 状态文案统一维护，例如 `task.status.waitingApproval`。
- 按钮使用具体动作：“停止任务”“批准本次命令”“立即安装并重启”，不使用含糊的“确定”。
- 错误信息包含：发生了什么、是否可重试、下一步操作和诊断 ID。
- Agent、Adapter、Session、Task、Team Profile 等技术名词在首次出现时提供简短解释或 Tooltip。

## 25. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 前端等待真实后端 | 项目停滞 | UiGateway + MockGateway + 版本化 Fixture |
| 页面直接绑定厂商 | 无法支持用户自定义团队 | 页面只识别 Role/Capability/Agent Instance |
| 后期补主题 | 大量硬编码返工 | F0 先完成语义 Token 和 ThemeEngine |
| 浅色完成后临时翻转深色 | 对比度和层级混乱 | 浅色/深色从第一天并行验收 |
| 主题切换闪烁 | 桌面体验差 | Vue 挂载前应用缓存主题 |
| 日志事件过多 | UI 卡顿 | 虚拟列表、批处理、上限和归档 |
| 自定义标题栏拖慢进度 | 跨平台窗口问题 | P0 使用原生标题栏，P1 再定制 |
| UI 只覆盖理想状态 | 联调后大量返工 | 每页强制 loading/empty/error/offline |
| 多套 UI 库冲突 | 包体和样式失控 | 只保留一套 Headless 基础，视觉统一自建 |
| OTA 时仍可创建任务 | 更新中产生数据丢失 | 维护模式全局 Gate + Task Drain 明确状态 |
